# Лабораторна робота №5: Взаємодія фронтенду та бекенду (AJAX, JSON)

П'ята практична робота з дисципліни «Сучасні технології розробки WEB-застосувань мовою програмування РНР». **Варіант 8: Система бронювання (готель/зали)**.

## Про проєкт
Цей проєкт демонструє сучасний підхід до розробки вебзастосувань, де клієнтська частина (фронтенд) взаємодіє з сервером (бекендом) асинхронно, без повного перезавантаження сторінки. Замість класичної генерації HTML на сервері, РНР-скрипти виконують роль API-ендпоінтів, які приймають та повертають дані у форматі **JSON**. Клієнтська логіка реалізована за допомогою сучасного JavaScript-інтерфейсу `fetch()` та `async/await`.

## Основний функціонал (AJAX)
- **Жива фільтрація (Live Search):** Пошук номерів за мінімальною місткістю відбувається миттєво під час введення тексту (подія `input`), оновлюючи таблицю без перезавантаження.
- **Асинхронне додавання (POST):** Надсилання форми додавання нового номеру перехоплюється JavaScript (`e.preventDefault()`). Дані відправляються на сервер у форматі JSON, після чого таблиця миттєво оновлюється новим записом.
- **Взаємодія з елементами (Бронювання):** Натискання кнопки «Забронювати» візуально змінює статус кімнати (змінює колір рядка та блокує кнопку) виключно засобами DOM API без звернень до сервера.
- **Обробка помилок:** Виведення повідомлень про помилки мережі або бази даних безпосередньо в інтерфейсі користувача (в окремому alert-контейнері), а не лише в консолі браузера.
- **Захист від XSS та SQL-ін'єкцій:** Усі отримані від сервера дані екрануються спеціальною JS-функцією `escapeHTML()` перед вставкою в DOM, а на бекенді використовуються підготовлені запити PDO.

## Структура директорій проєкту
- `/api_list.php` — ендпоінт (GET), що повертає список номерів у форматі JSON (підтримує параметр `?q=` для фільтрації).
- `/api_add.php` — ендпоінт (POST), що приймає JSON-тіло, додає новий запис у БД та повертає HTTP-статус операції (201 Created або помилки 400/500).
- `/db.php` — файл конфігурації та об'єктного підключення до БД `practicum4` (використовується з попередньої роботи).
- `/index.html` — головна сторінка з базовою HTML-розміткою (таблиця та контейнери для даних порожні, HTML генерується на клієнті).
- `/script.js` — клієнтська логіка: виконання `fetch()` запитів, обробка відповідей, маніпуляції з DOM.
- `README.md` — опис проєкту та інструкція.

## Як запустити та тестувати локально
1. Увімкніть вебсервер **Apache** та сервер баз даних **MySQL** у панелі XAMPP.
2. Переконайтеся, що база даних `practicum4` (з 4-ї лабораторної роботи) існує та налаштована.
3. Помістіть папку з файлами 5-ї лабораторної у директорію вебсервера (наприклад, `C:\xampp\htdocs\practicum05`).
4. Відкрийте браузер і перейдіть за адресою: `http://localhost/practicum05/index.html`.

### Перевірка AJAX (Інструменти розробника)
Щоб переконатися, що сторінка дійсно працює асинхронно:
1. Натисніть `F12` у браузері та перейдіть на вкладку **Network (Мережа)**.
2. У фільтрі виберіть **Fetch/XHR**.
3. Введіть цифру в поле пошуку або додайте новий номер — ви побачите миттєві фонові запити до `api_list.php` або `api_add.php`, а сама сторінка при цьому не моргатиме і не перезавантажуватиметься.
